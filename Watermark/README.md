# Watermark 2.0.0

## 关于

Watermark 是适用于 Typecho 1.2/1.3 的图片水印插件。它既可在文章输出时动态生成水印，也可将无水印原图保存到 Web 根目录之外，并让公开上传路径只保留水印成品。插件支持图片/文字水印、单点/平铺、旋转、透明度、尺寸过滤、路径排除、静态缓存、历史图片迁移和原图恢复。

独立仓库位于：https://github.com/NHPT/Watermark

> [!CAUTION]
> **私有原图目录保存着唯一可恢复的无水印版本。不要删除、清空、覆盖或放入临时目录。**
>
> 删除私有目录后，公开水印图仍能显示，但无水印原图无法由插件恢复。该目录必须纳入独立备份。

## 环境要求

- Typecho 1.2 或 1.3
- PHP 7.4 或 PHP 8.x
- GD 扩展
- 文字水印需要 GD FreeType 支持

## 安装

1. 从 [Releases](https://github.com/NHPT/Watermark/releases) 下载 `Watermark.zip`，
   解压到 `usr/plugins/`，最终路径应为 `usr/plugins/Watermark/`。
2. 在 Typecho 后台启用插件。
3. 保存水印设置。
4. 使用原图保护模式时，确认私有目录显示绿色“校验成功”。
5. 对已有站点执行“迁移或重新生成现有图片”。

GitHub 自动生成的 Source code 压缩包会带分支名后缀；需要免重命名安装时，
请使用 Releases 中的 `Watermark.zip`。

> [!WARNING]
> **从 1.x 首次升级到 2.0.0 前，必须先记录或截图保存全部旧设置。**
>
> 1.x 没有配置自动备份和恢复功能，而 Typecho 会在停用插件时删除普通插件配置。记录完成后，再停用并重新启用插件，使 2.0.0 的上传、替换和删除钩子生效，随后按记录重新核对设置。

## 工作模式

### 动态模式

动态模式在输出正文时将本地上传图片改写为签名 Action 或缓存地址，不修改 `usr/uploads` 中的原文件。

该模式不能保护原图。访问者仍可能直接请求公开的 `usr/uploads/...` 地址。

### 原图保护模式

保护流程如下：

1. 将无水印原图按 `usr/uploads` 后的相对路径保存到私有目录。
2. 始终从私有原图生成水印，避免重复叠加。
3. 在原 `usr/uploads` 路径写入水印成品。
4. 保存原图、水印图和配置的 SHA-256 状态。
5. 为公开水印 URL 添加内容版本，避免浏览器或 CDN 继续使用旧原图。

新上传和替换的图片会立即处理。正文中的未迁移历史图片会先改写为签名 Action，并在首次图片请求时迁移。建议仍执行后台批量迁移，以覆盖正文外图片并集中查看失败项。

保护模式采用失败关闭策略：水印资源无效、GD 失败或私有目录不可用时，Action 不会回退输出原图。

## 批量迁移范围

“迁移或重新生成现有图片”会扫描：

- `usr/uploads` 下全部 GIF、JPEG、PNG、WebP；
- 已在当前私有目录中登记的原图。

它不限于正文引用，因此也会处理未归档附件和其他存放在 `usr/uploads` 的业务图片。它不会扫描主题目录、插件目录或 `usr/img`。

命中图片排除规则、最小宽度或最小高度限制的图片不会绘制水印，而是按配置保留原样。

开始任务前，插件会显示候选总数、已是最新、未迁移和需要重新生成的数量。
已迁移且成品与当前配置一致的图片不会进入队列；待处理队列始终先迁移未受管图片，
再处理需要重新生成的图片。

管理员只需点击一次“一键处理全部”。服务端仍以每批最多 20 张的方式避免请求超时，
页面会自动续批并显示进度、成功项和失败项。任务状态保存在私有目录中，支持暂停、
关闭弹窗后继续、重新扫描以及只重试失败项。

扫描目录或处理批次期间，弹窗会显示当前阶段的加载状态和说明。候选、已完成、
待处理、失败及各类待处理数量会在每批完成后同步更新。

## 私有原图目录

默认目录位于站点根目录的同级位置：

```text
/path/to/.typecho-watermark
```

也可以在 Typecho 配置文件中锁定：

```php
define('__TYPECHO_WATERMARK_PRIVATE_DIR__', '/path/outside/web-root/watermark-originals');
```

常量优先于后台设置。使用常量后，后台不能切换私有目录。

> [!WARNING]
> 私有原图不能放在 `usr` 或其他 Web 可访问目录中。`open_basedir` 只限制 PHP，不会阻止 Nginx、Apache、LiteSpeed 或 IIS 直接提供静态文件。

### open_basedir 与权限

PHP 启用 `open_basedir` 时，私有目录必须加入允许路径：

```text
open_basedir=/path/to/site/:/path/to/.typecho-watermark/:/tmp/
```

配置位置取决于运行环境，可能是 `php.ini`、PHP-FPM 池、Web 服务器虚拟主机、`.user.ini` 或托管控制面板。修改后应重新加载对应的 Web/PHP 服务，或按托管平台要求等待生效。

Unix/Linux 示例：

```bash
mkdir -p /path/to/.typecho-watermark
chown <PHP运行用户>:<PHP运行组> /path/to/.typecho-watermark
chmod 700 /path/to/.typecho-watermark
```

Windows/IIS 应通过 NTFS ACL 授予对应应用程序池身份或 PHP 服务账户读写权限。

不要使用 `/tmp` 保存长期原图。

## 修改私有目录

私有目录已有原图后，后台会拒绝直接修改路径，防止将公开水印成品误登记为新原图并再次加水印。

需要变更目录时，使用设置页的“安全迁移私有目录”：

1. 初始化并验证目标目录。
2. 跳过目标目录中已经完整复制并校验的项目，其余原图及元数据每批最多处理 20 个。
3. 对每个原图执行 SHA-256 校验。
4. 全部文件和清单校验通过后，才切换数据库中的当前配置与备份配置。
5. 旧目录保持不动，用于回滚。

任一步骤失败时，插件继续使用旧目录，不会切换配置。确认新目录运行及备份正常后，旧目录才可由管理员另行归档或删除。

## 配置保存与恢复

Typecho 停用插件时会删除普通插件配置。Watermark 使用两条数据库记录避免配置丢失：

```text
plugin:Watermark
plugin:WatermarkBackup
```

- 每次保存设置时同步更新当前配置和备份。
- 停用前再次保存备份。
- 重新启用时从备份恢复。
- 保护模式备份指向的私有目录不可用时，插件会拒绝启用并显示错误。

数据库丢失、手动删除 `plugin:WatermarkBackup` 或迁移到新数据库后，配置无法自动恢复。此时必须重新指定原来的私有目录，不能把公开水印目录当作原图目录。

## 停用、删除、重装与升级

| 操作 | 公开图片 | 私有原图 | 配置 |
|---|---|---|---|
| 停用插件 | 已迁移图片继续显示水印；未迁移图片保持原图 | 保留 | 当前配置被 Typecho 删除，插件备份保留 |
| 重新启用 | 继续使用公开图片 | 重新关联原目录 | 从 `plugin:WatermarkBackup` 恢复 |
| 删除插件代码 | 公开文件不变 | 保留，不随插件目录删除 | 数据库备份通常保留 |
| 重新安装 | 公开文件不变 | 使用原目录重新关联 | 同一数据库中可恢复 |
| 原地升级代码 | 公开文件不变 | 保留 | 保留 |
| 更换数据库 | 公开文件不变 | 文件仍在磁盘 | 需要手动指定原目录 |
| 删除私有目录 | 水印图可能继续显示 | **无水印原图永久丢失** | 无法恢复原图 |

> [!IMPORTANT]
> **停用或删除插件不会自动恢复原图，也不会删除私有目录。**

## 退出保护模式

1. 在设置页执行“恢复公开原图”，点击一次后等待自动批处理完成。
2. 核对公开文件已恢复。
3. 切换到动态模式或停用插件。
4. 保留私有目录备份，确认无需回滚后再处理。

## 水印与过滤设置

- 图片水印和文字水印可单独或同时启用。
- 单点布局支持九宫格和随机位置。
- 平铺布局支持旋转和水平/垂直间距。
- 图片和文字透明度互相独立，`0` 为不透明，`100` 为全透明。
- 调整图片宽度只缩小超过目标宽度的图片。
- 最小宽高任一不满足时，图片保持原样。
- 动态 GIF 在动态模式下保持原图，在保护模式下拒绝处理。

图片排除列表每行一条规则，支持绝对上传路径、相对路径、文件名及 `*`、`?`：

```text
# 排除上传子目录
/usr/uploads/avatar/

# 相对于 usr/uploads
2026/qrcode.png
2026/private/*

# 匹配任意目录中的文件名
logo-*
*-no-watermark.png
```

## 缓存

动态模式缓存位于：

```text
usr/cache/watermark/
```

缓存键包含原图、水印资源、字体、布局和全部渲染设置。设置或文件变化后会生成新缓存。设置页提供带安全令牌的清理入口。

旧版本曾使用 `usr/img/` 作为缓存目录并清空其中全部文件。2.0.0 不会自动删除该目录中的任何内容，升级后应人工区分旧缓存与站点资源。

### 2.0.0

- 增加动态模式与原图保护模式。
